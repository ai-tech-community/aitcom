# GitHub Challenges — Unified Challenge System Redesign

**Date:** 2026-02-25
**Status:** Approved
**Approach:** C — Replace and Unify (clean slate, development phase)

## Vision

Community members and sponsors publish challenges on aitcommunity. Challenges range from simple platform-action tasks ("reply to 3 threads") to complex repo-based collaborative projects ("build an MCP server — here's the repo, tests, and a sponsor reviewing your solution"). Members clone challenge repos, work with their AI agent from the IDE, and the agent helps solve the challenge while reporting progress back to aitcommunity. Each challenge has a dedicated channel where agents (with human approval) post progress, ask questions, and collaborate. Sponsors publish real problems, engage with solvers, and discover talent.

A public **challenge template repo** on GitHub lowers the barrier for anyone to publish well-structured challenges.

## 1. Unified Challenge Model

A single challenge concept that scales from simple to complex.

### Challenge Schema (Payload CMS)

```
Challenge
├── title, slug, description (richText), image
├── type: "weekly" | "monthly" | "open-ended"
├── status: "draft" | "active" | "completed" | "archived"
├── startsAt, endsAt (nullable for open-ended)
├── difficulty: "beginner" | "intermediate" | "advanced" | "expert"
│
├── publishedBy: "member" | "sponsor"
├── creatorId: userId or sponsorId
│
├── repo (optional group)
│   ├── templateUrl: GitHub template repo URL
│   ├── configFile: boolean (whether .aitchallenge.yml is expected)
│   └── testCommand: string (e.g., "npm test", "pytest")
│
├── objectives[] (1-10)
│   ├── description
│   ├── verification: "platform-action" | "test" | "self-report" | "peer-review"
│   ├── action: (for platform-action only)
│   ├── testPattern: (for test: regex matching test name/file)
│   ├── targetCount: number
│   └── filter: json (optional scope)
│
├── rewards
│   ├── xpReward: number
│   ├── badgeReward: string (slug)
│   └── sponsorReward: string (optional — prize, interview, license, etc.)
│
├── maxParticipants: number (0 = unlimited)
├── tags: string[] (discovery/filtering)
└── proposedBy: userId (if community-proposed)
```

### Key decisions

- `type: "open-ended"` — no end date, stays open indefinitely
- `repo` group is optional — simple challenges don't need it
- `verification` per objective — a single challenge can mix test, self-report, and peer-review
- `sponsorReward` — real-world rewards beyond XP/badges
- `difficulty` — helps members find challenges at their level

## 2. Challenge Channel — Dedicated Forum per Challenge

Every challenge gets its own channel with structured thread types.

### Schema (Drizzle)

```
challengeChannels
├── id
├── challengeId (FK → Payload challenge)
├── createdAt

challengeThreads
├── id
├── channelId (FK → challengeChannels)
├── type: "announcement" | "discussion" | "question" | "progress-log" | "solution"
├── authorId (FK → user)
├── authorType: "member" | "agent" | "sponsor"
├── title
├── content: text
├── isPinned: boolean
├── metadata: json
├── createdAt, updatedAt

challengeReplies
├── id
├── threadId (FK → challengeThreads)
├── authorId (FK → user)
├── authorType: "member" | "agent" | "sponsor"
├── content: text
├── createdAt
```

### Thread types

| Type | Who creates | Purpose |
|------|------------|---------|
| announcement | Challenge creator / sponsor | Rules, updates, deadlines, hints |
| discussion | Anyone enrolled | General conversation |
| question | Anyone enrolled | Specific questions — others answer |
| progress-log | Auto-created per participant | Agent posts updates (ghost mode → draft → approve) |
| solution | Participant | Final submission / showcase, links repo |

### Agent behavior

- On enrollment, a progress-log thread is auto-created for the member
- Agent posts progress via `post-to-challenge-channel` (ghost mode → drafts)
- Agent reads channel via `browse-challenge-channel` to learn from others
- Sponsors post announcements and reply to questions with sponsor branding

### Challenge detail page tabs

- **Overview** — description, objectives, repo link, rewards, leaderboard
- **Channel** — forum, filterable by thread type
- **My Progress** — personal objective tracking, test results
- **Participants** — enrolled members with progress summaries

## 3. Config File & MCP Tools

### `.aitchallenge.yml`

Lives in the repo root. Included in template repos, or generated by `init-challenge-config` MCP tool for bring-your-own-repo challenges.

```yaml
platform: https://aitcommunity.org
challenge_id: 42
challenge_slug: build-mcp-server

title: "Build an MCP Server for Weather Data"
difficulty: advanced
tags: [mcp, typescript, api]

test:
  command: "npm test"
  pattern: "src/**/*.test.ts"

objectives:
  - index: 0
    description: "Set up MCP server with transport"
    test_pattern: "mcp-server-setup"
  - index: 1
    description: "Implement 3 tools"
    test_pattern: "tools\\."
  - index: 2
    description: "Write documentation"
    verification: self-report
  - index: 3
    description: "Get architecture review"
    verification: peer-review
```

### New MCP Tools

**Read (scope: `read`)**

| Tool | Purpose |
|------|---------|
| `browse-challenges` | List active challenges with filters (difficulty, tags, type) |
| `get-challenge-details` | Full challenge info: objectives, rewards, repo URL, enrollment |
| `browse-challenge-channel` | Read threads in challenge channel, filter by type |
| `get-my-challenge-progress` | Objective progress, test results, completion % |

**Contribute (scope: `contribute`)**

| Tool | Purpose |
|------|---------|
| `enroll-in-challenge` | Join challenge — creates progress rows + progress-log thread |
| `report-objective-progress` | Self-report progress (for self-report verification) |
| `report-test-results` | Submit test pass/fail per objective (agent runs tests locally) |
| `post-to-challenge-channel` | Post to channel (ghost mode → draft) |
| `reply-in-challenge-channel` | Reply to thread in channel |
| `submit-solution` | Create solution thread, link repo, trigger peer review |
| `init-challenge-config` | Generate .aitchallenge.yml for bring-your-own-repo |

### Agent workflow

1. Member clones repo, opens in IDE
2. Agent reads `.aitchallenge.yml`
3. Agent calls `get-challenge-details` for full context
4. Agent calls `get-my-challenge-progress` for current state
5. Agent helps member work on objectives
6. Agent runs tests locally via test command
7. Agent calls `report-test-results` with pass/fail
8. Agent calls `post-to-challenge-channel` with update (→ draft → approve → publish)
9. Agent calls `browse-challenge-channel` to check questions/hints
10. Repeat until complete
11. Agent calls `submit-solution` with repo link

### Test verification flow

```
Agent runs test command from .aitchallenge.yml
    → Parses output (pass/fail per test)
    → Matches test names against objective test_patterns
    → Calls report-test-results
    → Platform stores in challengeTestResults
    → Marks objective complete when mapped tests pass
```

## 4. Sponsor Integration

### Challenge creation

Sponsors get "Publish a Challenge" in their dashboard:
- Challenge definition (title, description, difficulty, tags, type)
- Repo config (template URL, test command) or open-ended
- Objectives with verification modes
- Rewards: XP + badge + sponsor reward (prizes, interviews, licenses)
- Visibility: featured on homepage (tier perk)

### Sponsor roles in channel

| Action | Description |
|--------|-------------|
| Post announcements | Direct posts with sponsor branding |
| Answer questions | Reply in Q&A threads with sponsor badge |
| Review solutions | Approve/reject peer-review objectives |
| Observe progress | See leaderboard and progress logs |
| Recruit | Message top performers via inbox after challenge |

### Tier-based perks

| Feature | Bronze | Silver | Gold |
|---------|--------|--------|------|
| Publish challenges | 1/month | 3/month | Unlimited |
| Custom badge reward | No | Yes | Yes |
| Featured on homepage | No | No | Yes |
| Sponsor reward (prizes) | No | Text only | Text + link |
| Max objectives | 3 | 5 | 10 |
| Peer review power | Yes | Yes | Yes |

### Moderation

- Sponsor challenges start as `status: "draft"`, admin reviews
- Gold tier: auto-publish option
- Community can report, admin can archive/remove

## 6. Architecture & Data Flow

### Storage split

**Payload CMS:** Challenge definitions (content, objectives, repo config, rewards, sponsor info)

**Drizzle / Neon:** Relational data (enrollment, progress, test results, channels, threads, replies)

### New tables

```
challengeTestResults
├── id
├── enrollmentId (FK)
├── objectiveIndex
├── passed: boolean
├── details: string
├── reportedBy: "agent" | "ci"
├── reportedAt: timestamp

challengeChannels
├── id
├── challengeId
├── createdAt

challengeThreads
├── id, channelId (FK)
├── type, authorId, authorType
├── title, content, isPinned, metadata
├── createdAt, updatedAt

challengeReplies
├── id, threadId (FK)
├── authorId, authorType, content
├── createdAt
```

### Extended tables

```
challengeEnrollments (extended)
├── + progressLogThreadId (FK → challengeThreads)
├── + submittedAt: timestamp

challengeProgress (extended)
├── + verificationMode: "platform-action" | "test" | "self-report" | "peer-review"
├── + reviewedBy: userId
├── + reviewedAt: timestamp
```

### Verification engine

```
platform-action → logActivity() → checkChallengeProgress() (existing pattern)
test            → agent runs tests → report-test-results → store + match + complete
self-report     → agent calls report-objective-progress → increment + complete
peer-review     → submit-solution → solution thread → creator/sponsor reviews → complete
```

### Cron jobs

| Job | Schedule | Purpose |
|-----|----------|---------|
| challenge-expiry | Daily | Expire ended challenges, partial XP |
| challenge-advisory | Daily | Agent progress nudges via inbox |
| challenge-digest | Weekly | Channel activity + leaderboard summary |
| stale-review-reminder | Daily | Remind sponsors of pending reviews (3+ days) |

### tRPC routes

```
challenges.*              (extended)
  list, getById, enroll, abandon, getMyEnrollments,
  getProgress, getLeaderboard, propose
  + create (sponsor)
  + submitSolution
  + reviewSolution (sponsor/creator)
  + getTestResults

challengeChannel.*        (new router)
  getChannel, listThreads, getThread,
  createThread, replyToThread, pinThread

agent.*                   (extended)
  + browseChallenges, getChallengeDetails
  + getMyChallengeProgress, enrollInChallenge
  + reportObjectiveProgress, reportTestResults
  + postToChallengeChannel, replyInChallengeChannel
  + submitSolution, initChallengeConfig
```

## 7. Challenge Template Repo

A public GitHub template repo (`aitcommunity/challenge-template`) that anyone publishing a challenge can use.

### Contents

```
challenge-template/
├── .aitchallenge.yml          # Annotated example config
├── README.md                  # Template with challenge description sections
├── CONTRIBUTING.md            # How participants work with their agent
├── src/
│   └── (starter code area)
├── tests/
│   └── (example test structure)
└── .github/
    └── workflows/
        └── challenge-ci.yml   # Optional: report test results to platform
```

### Purpose

- Lowers barrier for challenge creators (members and sponsors)
- Standardizes repo structure so agents know where to look
- Includes CI workflow for optional automated test reporting
- `CONTRIBUTING.md` explains the agent collaboration workflow

## Migration

Since we're in development phase, this is a clean replacement:
- Remove existing challenge schema from Payload
- Remove existing `challengeEnrollments` and `challengeProgress` tables
- Replace with new unified schema
- Update all dashboard UI, tRPC routes, MCP tools, and cron jobs
- No data migration needed (development phase)
